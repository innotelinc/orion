What the desktop does

Five workspaces behind one title bar, each reading or writing the machine through orion-api.

Files

Creates folders, writes uploads and renames or trashes entries on /srv/storage. Deletes move to .orion/trash, and images preview from the same byte stream you would download.

Services

The container's systemd units with their real state. Start, stop and restart call systemctl — including for nginx and the API themselves.

Storage

Every mounted filesystem with live capacity from statvfs, and the block devices exposed through /sys/block. No pool wizard, because a container cannot format host disks.

Settings

Kernel, runtime, CPU, memory and network facts read from /proc and resolvectl; only theme, accent and density are stored, and only in this browser.

Command palette

⌘K or Ctrl+K from anywhere to jump to a view, a file, a service or an action without leaving the keyboard.

Live telemetry

CPU, memory and interface rates sampled every two seconds on the host, so the charts show the machine rather than a random walk.

This deployment

A live deployment. The desktop writes the data volume and controls this container's services; the landing page and API are the only two things it serves besides the bundle.
